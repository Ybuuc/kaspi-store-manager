# ЛЗ 7 — STRIDE Threat Model

Жоба: Kaspi Store Manager  
Компонент: аутентификация және рөлдік қолжетімділік  
Күні: 13.10.2026

Ескерту: бұл — бастапқы дизайн моделі. Репозиторийде жұмыс істейтін authentication коды расталмаған. Құрал талап еткен нақты артефакт үшін OWASP Threat Dragon ішінде диаграмма жасап, JSON экспортын және скриншотын қосу қажет.

## 1. Компоненттер мен деректер ағыны
- External Entity: қызметкер/әкімші.
- Process: Web UI.
- Process: Auth/API.
- Data Store: User Store — пайдаланушы ID, password hash, рөл.
- Data Store: Audit Log — сәтті/сәтсіз кіру және рөлдік өзгеріс оқиғалары.
- Ағын 1: браузерден Auth/API-ға login деректері TLS арқылы.
- Ағын 2: Auth/API User Store-дан аккаунт және password hash оқиды.
- Ағын 3: Auth/API браузерге session cookie/token береді.
- Ағын 4: браузер қорғалған API-ға сессиямен сұрау жібереді.
- Ағын 5: API рөлді тексеріп, бизнес деректеріне қол жеткізеді.
- Ағын 6: Auth/API қауіпсіздік оқиғасын Audit Log-қа жазады.

Trust boundary: браузер мен сервер арасындағы желі; қолданба мен деректер қоймасы арасындағы шекара. Клиент жіберген рөлге немесе баға/қалдық мәніне сенуге болмайды.

## 2. STRIDE кестесі

| Санат | Қауіп сценарийі | Әсері | Бақылау шарасы | Тексеру дәлелі |
|---|---|---|---|---|
| S — Spoofing | Шабуылшы қызметкердің паролін пайдаланады | Аккаунтты басып алу | Argon2id/bcrypt hash, rate limit, қауіпсіз password reset, әкімшіге MFA қарастыру | Қате пароль және rate-limit тесттері |
| T — Tampering | Request ішінде role=admin немесе қалдық/баға ауыстырылады | Рұқсатсыз өзгеріс | Рөлді тек серверден алу, серверлік валидация, транзакция | Рөлді қолдан өзгерткен теріс API тесті |
| R — Repudiation | Қолданушы өзгерісті жасағанын жоққа шығарады | Ізге түсу мүмкін емес | Actor, timestamp, action, object сақтайтын audit log | Журналда төрт өріс бар |
| I — Information Disclosure | Қате хабарламасы аккаунт бар-жоғын немесе құпияны ашады | Дерек ағып кетуі | Біркелкі login қатесі, құпияны логтамау, TLS, least privilege | Жауап пен логта password/token жоқ |
| D — Denial of Service | Login endpoint-ке жаппай сұрау | Жүйе баяулайды/істен шығады | Rate limit, backoff, request-size limit, health check | Шектен асқанда 429 және service health |
| E — Elevation of Privilege | Staff admin операциясын шақырады | Әкімшілік функцияларды иемдену | Әр endpoint-та серверлік RBAC, deny-by-default, объект деңгейінде рұқсат | Staff admin операциясын орындай алмайды |

## 3. Қауіпсіздік талаптары
1. Парольдің өзін сақтамау; тек salt-пен қауіпсіз hash.
2. Тек TLS арқылы деректер жіберу.
3. Cookie қолданылса Secure, HttpOnly, SameSite атрибуттары және logout кезінде сессияны жарамсыз ету.
4. Cookie-based сессияда CSRF қорғанысын қолдану.
5. Құпияларды репозиторийге салмау; GitHub Actions secrets немесе secrets manager қолдану.
6. Рөлді клиенттен қабылдамау; әр API endpoint сервер жағында рұқсатты тексеруі тиіс.
7. Логтарда пароль, token және қажетсіз жеке дерек болмауы тиіс.

## 4. Threat Dragon орындау қадамдары
1. OWASP Threat Dragon веб-нұсқасын немесе desktop/offline нұсқасын ашу.
2. Жаңа модель құру: Kaspi Store Manager — Authentication.
3. Қатысушыларды, процестерді, деректер қоймаларын және алты ағынды диаграммаға енгізу.
4. Trust boundary белгілеу.
5. Әр ағын/компонентке STRIDE қауіптерін қосып, mitigation енгізу.
6. JSON экспортын және диаграмма скриншотын docs/security/lz7/ ішіне сақтау.
7. Әр қауіпке Open / Mitigated / Accepted мәртебесін беру.
