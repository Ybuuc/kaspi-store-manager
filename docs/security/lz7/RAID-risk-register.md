## Бағалау әдісі
P — ықтималдық, I — әсер, 1–5 шкаласы. Баға = P × I: 1–4 төмен, 5–9 орташа, 10–15 жоғары, 16–25 сыни. Қайта қарау: көрсетілген күнде және триггер болғанда дереу.

Жеке жауапты ретінде уақытша Ораз Дінмұхаммед Қанатбекұлы (жоба иесі) белгіленді, себебі команда мүшелерінің аты-жөні қолда жоқ. Команда құрамы бекітілгенде әр тәуекелдің иесін нақты орындаушыға беру қажет.

## Top-5 тәуекел — толық жоспар

### R10 — Сыйымдылық пен мерзім
Себеп: ЛЗ 5 бағалауында backlog 92 сағат, capacity 68 сағат; айырма 24 сағат. Салдары: кешігу, тест уақытын қысқарту, сапаның төмендеуі. Триггер: жұмыс көлемі 68 сағаттан асуы немесе milestone-ға дейін негізгі тапсырмалардың 20%-дан астамы аяқталмауы. Әрекет: MVP Must Have функцияларын бірінші орынға қою, қосымша функцияларды кейінге қалдыру, апта сайын remaining effort есептеу. Қалдық тәуекел: орташа.

### R20 — Сканерлеудің болмауы
Себеп: Trivy/gitleaks есебі әзірге расталмаған. Триггер: негізгі branch-ке скан нәтижесінсіз commit біріктіру немесе workflow failed. Әрекет: merge-ді тоқтату, finding-ті triage ету, осал пакетті жаңарту; secret табылса revoke/rotate. CI-де скан міндетті болсын. Қалдық тәуекел скан тұрақты орындалған соң ғана қайта бағаланады.

### R01 — Репозиторийдегі құпия кілттер
Триггер: gitleaks finding немесе кілттің жарамды екені анықталуы. Әрекет: кілтті дереу revoke/rotate, commit тарихын тексеру/тазарту, қолжетімділік журналын тексеру. Файлды жай өшіру бұрынғы commit-тегі кілтті жарамсыз етпейді.

### R02 — Рөлдік қолжетімділік
Триггер: қарапайым қызметкер admin endpoint шақыра алады немесе рөлді request ішінде өзгертіп, құқық алады. Әрекет: серверде әр endpoint үшін RBAC; deny-by-default; рөлдерге оң және теріс тесттер; code review.

### R03 — Жеке деректер
Триггер: кез келген дерек өрісіне мақсат, заңды негіз, сақтау орны, қолжетімділік немесе сақтау мерзімі белгіленбеген. Әрекет: деректерді минимизациялау; қажет емес өрістерді алып тастау; заңдық негізді және retention-ды жауапты тұлғамен бекіту.
