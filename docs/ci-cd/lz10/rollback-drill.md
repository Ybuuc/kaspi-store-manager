# Протокол учебного отката — 03.11.2026

Место: отдельная установка localhost, созданная исключительно для тренировки.
Все пользователи, товары и заказы синтетические. Пользовательская БД не использовалась.
Это **не production-инцидент**; результаты не включаются в MTTR/CFR.

| Проверка | Фактический результат |
|---|---|
| Предыдущая версия | `ab275bbccdaa5b4f49ccb43819a09e194d7850a5` |
| Проверяемый пакет | `c252f21867463d0a2adf1beb0501806f51f12486` |
| SHA-256 файлов пакета по манифесту | Совпадают |
| Резервная копия SQLite | Создана через backup API; содержимое совпало с исходным |
| Имитация неисправного выпуска | Контролируемый ответ HTTP 503 на отдельном тестовом процессе |
| Возврат к предыдущему пакету после обнаружения 503 | **0,684 с**, включая остановку, запуск и smoke |
| Заказ после backup | Сохранён при откате кода: 1 → 2 заказа |
| Отдельная проверка восстановления повреждённой тестовой БД | **0,671 с**, включая сохранение повреждённой копии, восстановление и smoke |
| Данные восстановленной БД | Полностью совпали с backup |
| SQLite integrity_check | `ok` |
| HTTP smoke | `/login` 200; анонимный каталог → login; вход сотрудником; товар DRILL-SKU виден; `/orders` 200 |
| Цель ≤15 минут | Выполнена в автоматизированной локальной тренировке |

Время отсчитывается от обнаружения имитированной ошибки до завершения
автоматических smoke и проверки данных. В сценарии восстановления БД — от начала
операций восстановления до окончания тех же проверок.

Ограничения: текущий релиз меняет CI, документы и инструменты; `app.py` в двух
пакетах одинаков. Использовано одно локальное Python-окружение. Не проверялись
сетевая инфраструктура, ручное принятие решения и 15-минутное наблюдение.
В отдельном сценарии восстановления БД не было записей после backup;
сверка и повторный ввод потерянных операций не отрабатывались.
Эти измерения не являются подтверждённым production RTO или MTTR команды.

## Воспроизведение

Из корня репозитория с установленными `requirements.lock`:

```powershell
python tools/rollback_drill.py --work-dir ../new-rollback-drill --report ../rollback-drill-result.json
```

Каждый запуск требует нового `--work-dir`. Скрипт не перезаписывает предыдущую
тренировку; работает только с созданными им fixture-базами и процессами.
Оба HTTP-сервера завершаются по окончании проверки.
