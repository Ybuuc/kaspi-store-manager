# Защита main и ревью

Целевая политика main:

- Изменения через PR, **минимум одно независимое approve**.
- Новый commit сбрасывает устаревшее approve.
- Обязательные CI checks: `lint`, `test`, `dependencies`, `build`.
- Ветка PR должна содержать актуальную main; все обсуждения разрешены.
- Force push и удаление main запрещены.
- Защита распространяется на администраторов.

Владелец и разработчик: **@Ybuuc**. Независимый reviewer пока не назначен:
преподаватель или другой участник с write-доступом. Автор PR не может одобрить
собственную работу. Одному студенту правило не даёт обходного «саморевью»:
до назначения reviewer последующие PR останутся заблокированы, что ожидаемо.

Reviewer проверяет бизнес-сценарии каталога, цен, остатков и заказов;
наличие тестов на изменённое поведение; SQL/CSRF/роль пользователя;
результат Trivy; совместимость SQLite и релизный rollback.
Approve — после зелёных checks, вопросы — через Request changes.
Секреты, БД пользователей и выгрузки магазина не публикуются в артефактах.

Проверка настройки: Settings → Branches → правило `main`;
скриншоты фактической настройки сохраняются рядом с отчётом.
Файл политики сам по себе не включает защиту — требуется сохранённое правило GitHub.
