# ЛЗ1: подтверждённые данные и открытые пункты

Сборщик `python tools/collect_vacancies.py` использует открытый API HeadHunter,
проверяет archived=false, отбирает 10 PM/Delivery/PO/BA-PM вакансий Казахстана,
сохраняет ссылки, даты и частоты кодов требований. Полные объявления не копируются.
В этой среде API вернул **403**, поэтому 10 актуальных вакансий и итоговая частотная
таблица **не получены**. Повторить сбор локально или предоставить 10 публичных ссылок.
Автоматическое кодирование ключевыми словами требует ручной проверки полноты.
Группы частот: ≥50%, 20–<50%, <20%; порог 50% включён в первую группу.

Личная карта компетенций не может быть заполнена по предположению:
для каждой категории из collect_vacancies.SKILLS поставить есть/частично/нет,
приложить свой пример и одно действие на семестр с датой.

## Разбор проблемного проекта: ранний Universal Credit, 2013

Источник: [National Audit Office, Universal Credit: early progress](https://www.nao.org.uk/reports/universal-credit-early-progress-2/), 05.09.2013.
Аудитор отмечал слабость управления и контроля при ограниченном плане;
в ранней реализации списано 34 млн GBP ИТ-активов. Это не утверждение,
что вся программа окончательно провалилась: анализ ограничен ранним этапом.
Управленческая ошибка по выводам аудитора — недостаточный контроль состояния
программы и финансов при сложной новой поставке. Сигнал можно было выявить
до расширения внедрения: независимая проверка работающего сквозного сценария,
сопоставление оплаченных результатов и принимаемых пользовательских функций.
Предлагаемые нами артефакты: проверяемые критерии приёмки, журнал рисков,
вехи с доказательствами результата и право остановить финансирование этапа.
Это рекомендации по анализу источника; они не доказывают, что один документ
гарантированно предотвратил бы проблемы программы.

## Карточка проекта

Kaspi Stock: учёт складских товаров, поступлений, продаж и прибыли малого магазина.
Заказчик: владелец магазина — имя и подтверждение участия ещё не предоставлены.
Команда: 2 человека (подтверждено пользователем), имена и согласование ролей ожидаются.
Проблема-гипотеза: разрозненный учёт и ручные операции; исходный замер отсутствует.
Цель-гипотеза: экономия 20 часов/месяц, проверяется интервью и замером, не считается достигнутой.
