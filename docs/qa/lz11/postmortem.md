# Blameless postmortem — учебный отказ HTTP 503

**Класс:** учебная имитация, **не реальный production-инцидент**. **Дата упражнения:** 03.11.2026. **Источник фактов:** [ЛЗ10 — rollback drill](../../ci-cd/lz10/rollback-drill.md), [пустой production incident register](../../ci-cd/lz10/data/incidents.json). **Дата разбора:** 12.11.2026.

## Обзор / влияние
Во время изолированной тренировки вместо рабочего выпуска на контролируемом тестовом процессе вернулся HTTP **503**. Цель — проверить способность команды вернуть предыдущий локальный пакет и подтвердить сохранность синтетических данных. **Влияние на реальных клиентов и бизнес: отсутствует по определению среды**; охват ограничен локальными тестовыми процессами. Production MTTR, CFR и SLA на основе эксперимента **не вычисляются**.

## Хронология — подтверждённые этапы (точных wall-clock timestamp в отчёте нет)
1. **Подготовка:** тестовая БД, копия с использованием SQLite backup API и два проверяемых программных пакета.
2. **T0:** намеренный ответ 503 от отдельного тестового процесса; это точка отсчёта измерения.
3. **После T0:** остановка проверочного процесса, старт прежнего пакета и HTTP smoke. Замер от обнаружения 503 до успешного smoke: **0,684 с** в автоматизированной локальной тренировке.
4. **Отдельное упражнение:** имитация повреждения *тестовой* БД → восстановление из backup → `integrity_check = ok` и smoke за **0,671 с**. Это независимый эксперимент, не продолжение 503.
5. **После:** подтверждён login, каталог, учебный заказ, заказ после backup не потерялся при *откате кода*. Реальных оповещений Uptime Kuma в момент тренировки не существовало/не зафиксировано.

## Какие факторы внесли вклад (без поиска виновных)
- Отказ был **инъекцией для проверки процедуры**, а не ошибкой конкретного участника.
- В локальной версии пока нет зарегистрированного демонстрационного мониторинга с доказательствами UP/DOWN; обнаружение 503 в упражнении было управлямым.
- Ручные backup и однократный rollback не заменяют регулярные копии, а реальное время принятия решения и 15-минутное наблюдение не измерялись.
- Код приложения в сравненных двух пакетах идентичен; не следует приписывать им реальную регрессию.

## Что сработало / что улучшить
Сработали: согласованный SQLite backup, проверка контрольных сумм пакета, быстрое восстановление предыдущего тестового пакета, HTTP и DB smoke. Улучшить: проверяемое обнаружение недоступности, ежедневные резервные копии со сроком хранения, обязательный pre-release gate с повторяемым rollback.

## Проверка корректирующего механизма — 12.11.2026

В **отдельном** CI-прогоне [Live QA #43280650094](https://github.com/Ybuuc/kaspi-store-manager/actions/runs/43280650094) реализована и реально проверена одна из мер обнаружения: Uptime Kuma v2 в Docker создал HTTP-монитор, затем автоматизированный Playwright воспроизвёл **UP → DOWN → UP**, когда учебный контейнер приложения был остановлен и заново запущен. Результаты и снимки хранятся в [evidence](https://github.com/Ybuuc/kaspi-store-manager/actions/runs/43280650094/artifacts/13973270776). Это новое независимое **учебное упражнение**, не фактическое продолжение события 03.11.2026 и не production-метрика доступности. Для полного закрытия [#64](https://github.com/Ybuuc/kaspi-store-manager/issues/64) всё ещё нужны постоянный демо-стенд, интервал 60 секунд, канал уведомления и подтверждение его работы; CI-монитор был временным, с интервалом 20 секунд ради краткой тренировки. Другие действия #65 и #66 остаются открытыми до выполнения DoD.

## Результат расширенного упражнения — 12.11.2026

В [CI #43291242294](https://github.com/Ybuuc/kaspi-store-manager/actions/runs/43291242294) прежний релиз `main` и новый кандидат были реально развернуты на отдельных временных каталогах, затем в кандидат введён HTTP 503. Откат пакета и smoke заняли **0,255 с**, отдельный rollback тестовой SQLite из backup — **0,251 с**, `PRAGMA integrity_check=ok`; заказ, созданный после снимка, сохранялся при откате *кода* (число учебных заказов 1→2). Это только автоматизированный учебный опыт на одном runner, не production MTTR. [CI gate #43290958703](https://github.com/Ybuuc/kaspi-store-manager/actions/runs/43290958703) подтверждает выпуск при успешных 37 тестах и smoke; независимый UAT остаётся открытым.
