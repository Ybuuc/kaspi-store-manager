# Сценарии UAT (версия 1.0 от 12.11.2026)

**Роли:** C — участник другой команды в роли заказчика; QA — координатор; приложения используются только с учебными данными. Перед началом QA фиксирует commit SHA, дату и чистую базу. Для UAT-10 требуется Admin. Каждый шаг воспроизводится вручную самим C; автоматический тест не заменяет независимую приемку.

| ID / критичность | Предусловия и действия заказчика | Измеримый критерий PASS |
|---|---|---|
| **UAT-01 / P1** Вход/выход | Пользователь Employee создан. Открыть `/login`, войти корректным паролем, затем выйти; повторить с ошибочным паролем | Корректный вход открывает `/products`; после выхода доступ требует входа; неправильный пароль не открывает каталог и не раскрывается |
| **UAT-02 / P1** Создание товара | Employee. Создать «Учебный чай», SKU `UAT-TEA-<суффикс>`, 1500.00, остаток 2; повторить SKU | Товар виден в каталоге и карточке, цена и количество сохранены; повторный SKU отклонён без дублирования |
| **UAT-03 / P2** Поиск и пустой результат | Создан «Учебный чай». Найти по части названия с другим регистром; ввести несуществующий запрос | Найден именно созданный товар; при пустом результате явное сообщение и нет чужих товаров |
| **UAT-04 / P1** Low-stock | На товаре UAT-02 порог 3, остаток 2; затем изменить остаток на 4; очистить порог | При 2 < 3 показано предупреждение; при 4 предупреждения нет; при пустом пороге не появляется |
| **UAT-05 / P2** Цена и история | Employee меняет цену товара 1500.00 → 1600.00; Admin открывает «Баға тарихы» | Новая цена видна после повторного открытия; история содержит обе цены, время и имя редактора |
| **UAT-06 / P2** Архив | Employee архивирует товар, проверяет каталог/архив; восстанавливает | Товар пропал из активного списка и появился в архиве; после восстановления снова виден |
| **UAT-07 / P1** Статусы | Есть учебный заказ «Жаңа». Сменить на «Өңделуде», потом «Орындалды»; попытаться изменить конечный статус | Допустимые переходы сохраняются при обновлении; конечный статус неизменяем; запрос запретного перехода не изменяет данные |
| **UAT-08 / P1** Сумма продаж | Admin, 3 учебных заказа за один день: 1000.00 «Орындалды», 500.00 «Бас тартылды», 200.00 «Жаңа»; выбрать день в отчёте | Число заказов = 3; сумма продаж = 1000.00; отмененный и новый не увеличивают сумму |
| **UAT-09 / P1** Разграничение доступа | Employee после входа открывает `/admin`, `/reports/sales`, `/admin/audit` прямым URL | HTTP 403 для всех административных URL; никаких административных данных в ответе |
| **UAT-10 / P2** Отчёт и аудит | Admin. Посмотреть складской отчёт, изменить остаток, затем открыть «Өзгерістер журналы» | Количество активных товаров и low-stock соответствует каталогу; в audit log есть действие, actor и timestamp |
 
**Особенности:** UAT-08 требует синтетических заказов, созданных через `add-demo-order` в *отдельной* базе. Перед повтором не создавать дубликаты заказов. Для отрицательного UAT-07 выполнить проверку только на тестовой базе, не на реальном бизнесе. Проверка UAT-09 проводится по реальным HTTP-кодам (вкладка Network/devtools), а не только по отсутствию ссылки.

**Завершение:** для каждого ID в протоколе записать факт, evidence, PASS/FAIL/BLOCKED и issue при отклонении. Для замечаний использовать P0 (критическая потеря данных/компрометация), P1 (блокер приемки), P2 (существенное, обход есть), P3 (косметика); создавать отдельный GitHub Issue с шагами, expected/actual, средой, UAT ID, приоритетом. Не выдумывать замечания при отсутствии реальной проверки.
