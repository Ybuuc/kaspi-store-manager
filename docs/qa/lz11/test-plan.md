# План тестирования — Kaspi Store Manager

**Версия:** 1.0, 12.11.2026. **Объект:** текущий инкремент MVP + Business Operations (US-01…US-18) из основного репозитория. **Заказчик UAT:** другая учебная команда, пока не назначена.

## 1. Объём и границы

Включены: вход/выход и блокировка после пяти ошибок; CRUD каталога, уникальный SKU, поиск/архив; цена и история; остаток и индивидуальный low-stock threshold; учебные заказы и допустимые переходы статуса; отчёты; Employee/Admin, CSRF и аудит; резервирование SQLite; доступность HTML демо.

Исключены из приёмки до отдельной реализации: реальный Kaspi API, платежи, production-HTTPS, реальная 24/7-доступность, подтверждённая нагрузка 200 пользователей и ежедневный автоматический backup. Не выдавать учебные заказы за реальные продажи.

## 2. Уровни и инструменты

| Уровень | Что проверяем | Инструмент | Критерий |
|---|---|---|---|
| Unit | `price_cents`, `stock_value`, переходы статусов, валидация, хэширование | `pytest` (включая имеющиеся `unittest`) | 100% тестов успешно; P0/P1 = 0 |
| Integration | Flask client + отдельная SQLite: login, права, CSRF, таблицы и аудит | `pytest`, `tests/test_app.py` | Все автоматические проверки зелёные |
| HTTP/API contract | HTTP 200/302 и проверка запрета доступа на страницах | Bruno (открытый клиент HTTP) | Код, Location и тело соответствуют ожиданию |
| E2E GUI | Вход сотрудника, список товара, отказ прямого доступа | Playwright Chromium; вручную Edge | Критические пользовательские пути без ошибок |
| Load | Чтение каталога после авторизации, p95/error rate | k6 (отдельный подготовленный стенд) | NFR-01: 200 VU, p95 ≤800 мс; ошибки <1%, при соблюдении стендовых ограничений |
| Operations | Отклик страницы входа, оповещение о недоступности | Uptime Kuma 2 через Docker Compose | UP и контролируемый DOWN подтверждены доказательствами |
| UAT | 10 сценариев пользователя с независимым заказчиком | Ручной протокол + GitHub Issues | Подписанное решение и нет P0/P1 |

Приложение сейчас HTML/Flask, **отдельного REST JSON API нет**. Bruno проверяет HTTP-контракты HTML-маршрутов, не заявленную интеграцию с Kaspi. Нагрузочный скрипт читает каталог и **не подтверждает** NFR-02 для массовых записей; отдельный write-тест нужен на удаляемом синтетическом стенде. Обычный `flask run` не является production WSGI-сервером: NFR-01 тестируется лишь как учебная проверка, результаты не экстраполируются на production.

## 3. Окружение и тестовые данные

- **CI:** GitHub Actions, Python 3.12, Flask из `requirements.lock`, SQLite в `tempfile`. Тесты не используют пользовательскую БД.
- **Локальная GUI-приёмка:** Windows/Linux, `127.0.0.1:5000`, Chromium/Edge, отдельная база в Docker volume или временном каталоге, режим `KSM_SECRET_KEY` с новым случайным значением; пароли передаются вне Git.
- **Фикстуры:** аккаунты `admin` и `employee`; 2–3 товара (`UAT-TEA-<суффикс>`, `UAT-COFFEE-<суффикс>`), цена 1500.00/2000.00, остаток 2/5, порог 3; учебные заказы `Жаңа`, `Орындалды`, `Бас тартылды` с датой сеанса; пустая база для empty state; отдельная база с 100 и 10 000 позициями для перформанса.
- **Защита:** никаких боевых клиентов, токенов Kaspi и личных данных; не коммитить `.env`, SQLite, пароли, скриншоты с сессиями; отдельные тестовые учетные записи и очистка после UAT.

## 4. Матрица рисков и критериев выхода

| Риск | Тест | Условие блокировки |
|---|---|---|
| Утечка прав Admin | Переход на `/admin`, `/reports/sales`, `/admin/audit` под Employee | Любой несанкционированный доступ: P0/P1 |
| Потеря данных | Перезапуск, backup/restore в изолированной БД | Повреждение или потеря заказов: P0 |
| Недействительные заказы | Завершённый статус → другой | Ошибочный переход: P1 |
| Неправильная сумма продаж | Исключить отменённые/незавершённые из суммы | Неверный отчёт: P1 |
| Регрессия каталога | SKU, архив, поиск и low-stock | Нарушенный основной сценарий: P1 |
| Недоступность демо | Kuma + ручной HTTP smoke | В момент UAT стенд недоступен |

**Exit gate:** все существующие тесты и тесты ЛЗ11 проходят; 10 UAT-сценариев выполнены другой командой, 100% критических UAT-01/02/04/07/09 = PASS, нет P0/P1, найденные P2/P3 внесены в GitHub; заказчик записал Accept / Conditional accept / Reject. `coverage ≥70%` (NFR-14) проверяется отдельным отчётом, нельзя писать «достигнуто» без измерения. Настоящее RPO≤15 мин / ежедневное резервирование по NFR-05/11 пока не подтверждены.

## 5. Воспроизведение

```powershell
# После установки Python 3.12 из корня репозитория:
python -m pip install -r requirements.lock
python -m pip install pytest
python -m pytest -q tests/test_app.py tests/lz11/test_contract.py
# Дополнительно UI (после подготовки тестовых пользователей и отдельного стенда):
python -m pip install playwright
python -m playwright install chromium
$env:KSM_BASE_URL = "http://127.0.0.1:5000"
$env:KSM_UAT_USER = "employee"
$env:KSM_UAT_PASSWORD = "<пароль тестового employee>"
python -m pytest -q tests/lz11/test_browser.py
# нагрузка — устанавливается k6, затем:
# k6 run -e KSM_BASE_URL=http://127.0.0.1:5000 -e KSM_USER=employee -e KSM_PASSWORD=<секрет> tests/lz11/load/read_catalog.js
```

Браузерный тест требует созданной учётной записи; секрет вводится только локально. Для UAT обязательно сохранить: SHA, версию Python/browser/ОС, базу-фикстуру, тест-лог, скриншоты и ссылки на замечания.
