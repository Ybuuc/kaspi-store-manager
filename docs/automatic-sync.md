# Автоматическое обновление при запуске

После однократной настройки приложение само запускает фоновое чтение источников
при старте и повторяет проверку каждые 300 секунд. Открывать кнопку обновления
для этого не требуется. Внешние операции — только GET, кабинет не изменяется.

## Два источника

1. **API Kaspi**: заказы, статусы, состав, количества/суммы позиций и карточки
   товаров из заказов. Используется ваш KASPI_API_TOKEN. Новые записи сохраняются
   в той же базе; повторный импорт не списывает физический склад повторно.
2. **HTTPS XML-прайс продавца**: полный доступный в прайсе ассортимент, цены
   по городам, наличие/количество по складам и сроки предзаказа. Используется
   прямая ссылка KASPI_CATALOG_URL на ваш обновляемый прайс. Токен Kaspi на этот
   сервер не передаётся. Прежние снимки и складская история сохраняются.

В проверенной публичной документации API нет подтверждённого GET полного
каталога продавца с текущими остатками. Раздел API «Товары» описывает добавление
карточек и результаты импорта, а API заказов — товары в конкретном заказе:
[возможности API](https://guide.kaspi.kz/partner/ru/shop/api/general/q3193),
[API товаров](https://guide.kaspi.kz/partner/ru/shop/api/goods),
[состав заказа](https://guide.kaspi.kz/partner/ru/shop/api/orders/q3203).
Поэтому не используется выдуманный GET /products и данные заказов не выдаются
за полный склад. XML-формат: [Kaspi Гид](https://guide.kaspi.kz/partner/ru/shop/goods/price_list/q2962).

Ссылка должна возвращать сам XML без формы входа и перенаправления. Она должна
принадлежать вашему магазину и обновляться вашей системой учёта/поставщиком
прайса. Размещённый однажды статический ACTIVE.xml сам не становится свежим.
Дата внутри файла всегда показана отдельно от времени успешного скачивания;
повторное скачивание старого файла не объявляется новой инвентаризацией.
Предзаказ и stockCount не приравниваются к подтверждённому физическому наличию.

## Однократная настройка

В папке с app.py создайте локальный .env по примеру .env.example:

```dotenv
KSM_SECRET_KEY=ваш-постоянный-случайный-ключ
KASPI_API_TOKEN=ваш-токен-кабинета
KASPI_AUTO_SYNC=1
KASPI_SYNC_INTERVAL_SECONDS=300
KASPI_HISTORY_DAYS=14
KASPI_CATALOG_URL=https://ваш-сервер/ваш-обновляемый-прайс.xml
```

Токен, постоянный ключ приложения и URL с секретными параметрами храните только
локально. Не добавляйте .env в Git и не присылайте секретную ссылку в чат.
Переменные окружения имеют приоритет перед .env.

Сохраните резервную копию app.db. Установите зависимости и выполните init-db,
чтобы добавить служебную таблицу расписания. Старые записи не удаляются.

```powershell
.\.venv\Scripts\python.exe -m flask --app app:create_app init-db
.\.venv\Scripts\python.exe app.py
```

Вход: http://127.0.0.1:5000/management/login. Если администратора ещё нет,
однократно выполните create-user --role admin admin, как в integration.md.

Другой способ запуска с немедленным автообновлением:
`python -m flask --app app:create_app serve`.
Устаревший `flask run` также поддержан: фоновый цикл стартует при первом
обращении к веб-серверу. Простое создание Flask-приложения, init-db, автотесты
и API import worker не запускают дополнительные циклы или сетевые запросы.

В Docker штатный gunicorn загружает wsgi:app, который запускает цикл при
старте веб-процесса. Для ручного gunicorn используйте тот же wsgi:app без
--preload. Предварительно инициализируйте app-data и администратора.
Docker здесь не запускался: поведение проверено кодом и локальными тестами.

## Надёжность и контроль

- Служебная lease в SQLite разрешает один цикл для всех веб-процессов.
  Действующая загрузка заказов не запускается повторно. После аварии lease
  каталога истекает через 10 минут; зависшая очередь API — через 2 часа.
- Веб-запрос не ждёт синхронизацию: XML проверяется в фоновом потоке, API —
  в отдельном процессе. Неизменившиеся подтверждённые заказы не запрашивают
  повторно сотни одинаковых составов при каждом цикле. Состав активного заказа
  читается каждый цикл; кэш состава неизменного архивного заказа живёт до суток.
  Изменение родительского заказа или отсутствие даты проверки сбрасывает кэш.
- Сетевые ошибки, HTTP 401/403/429, неверный XML и ошибка записи не подменяются
  успешным пустым импортом. Предыдущая база остаётся доступна. Следующий цикл
  повторяет попытку с настроенным интервалом, без непрерывных повторов.
- Сбой прайса не останавливает чтение заказов; отсутствие токена не останавливает
  прайс. Смена продавца, более старый XML, дубли и неверные количества отвергаются.
- Скачивание: HTTPS/TLS, без редиректов, ограничение 16 МБ и времени; нет токена
  Kaspi в заголовках прайса. URL с секретом и HTTP-ответы не попадают в журнал.
- Панель администратора показывает состояния API/XML, последнюю попытку,
  успешное скачивание прайса, дату самого XML и следующую проверку.
  Машинный статус — /api/kaspi/status; доступ только администратору.

KASPI_AUTO_SYNC=0 выключает фоновый цикл. Приложение продолжает показывать
сохранённые данные с датами источников; ручная синхронизация остаётся доступна.
Интервал допустим от 60 до 86400 секунд. Цикл работает, пока приложение запущено;
при выключенном компьютере запросы не выполняются.

Локальный HTTPS с обязательной проверкой TLS: [local-https-catalog.md](local-https-catalog.md).
